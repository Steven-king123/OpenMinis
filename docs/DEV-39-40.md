# Minis Dev 39–40: glass controls, fixed wallpaper and native math repair

These changes extend the Dev 38 source on `feature/advanced-memory`; they do not replace the upstream `main` branch. Development APKs are built on the configured private server, not automatically by GitHub Actions. The existing workflow remains manual-only.

## Dev 39 — optional glass and input-aware wallpaper

- Added independently persisted **Glass chat controls** and **Resize background with input** switches, both defaulting to off.
- Glass uses pinned **Haze 1.6.10** (Apache-2.0) for actual backdrop blur on Android 12/API 31 and later. Earlier versions use an opaque fallback; foreground text, icons and thumbnails are not blurred.
- Applied to the top bar, main composer, add/slash/idle microphone controls, and floating **Minis Computer** status bar. Expanded tool detail pages retain their original surfaces. Message backplate opacity remains independent.
- Wallpaper is drawn once in a complete chat viewport source, separately from controls and the message-list source. With resizing off it is outside IME padding; with resizing on its canvas follows IME-available height. Rotation and real window-size changes still adapt normally.
- One isolated preview combines wallpaper, theme dimming, message opacity, glass controls and a simulated keyboard.
- Top-bar sampling and the duplicate adaptive wallpaper layer were corrected before delivery.

Dev 39 passed 53 targeted tests and APK signature/checksum verification. These are not claims of pixel-perfect device rendering or universal OEM keyboard behavior.

## Dev 40 — native display-math parsing

The screenshot defect was in Markdown recognition, not unsupported KaTeX syntax: a paragraph could consume an immediately following display opener, then generic inline escaping removed LaTeX backslashes. A short 14-character ratio was affected too.

- Introduced a shared bounded `DisplayMathBoundary` scanner for line-leading `\[…\]` and `$$…$$` pairs, with fenced-code shielding and structural recovery boundaries.
- Paragraphs now stop at valid display openers without requiring an extra blank line.
- Prefragmentation preserves complete formulas and their internal blank lines before independently rendering chat rows. Incremental sealed-boundary logic follows the same protection.
- List, task-list and quoted formulas retain their mathematical structure. Mixed list children such as fenced code use actual block rendering rather than flattening into inline text.
- Unclosed formulas remain recoverable literal `RawMath`, including internal blank lines, instead of prematurely rendering incomplete mathematics or removing command backslashes. Recovery stops at structural boundaries and bounded limits.
- Markdown escapes are restricted instead of unconditionally stripping every backslash. Formula suffixes are consumed iteratively, and heading detection is shared to avoid non-advancing `#tail` parsing.
- Preserved KaTeX, existing wide-equation layout, search/selection infrastructure, glass/background options, model search and advanced memory. No message rewriting, model calls, WebView reading mode, new permissions or math-rendering dependency was added.

### Verification

The private-server Android build succeeded. **192 targeted Kotlin/JVM tests in 21 classes passed**, with zero failures, errors or skips. This includes **36 new math tests**, exact mathematical bodies from the reported screenshots with neutral surrounding text, semantic `MathDisplay` assertions, internal blanks, nested structures, streaming cuts, code isolation and recovery. Relevant existing Markdown, search, advanced-memory and appearance tests also passed.

The user subsequently reported normal behavior in the scenarios they tested. This is useful device feedback, not exhaustive validation across devices, formulas or layout conditions. Ultra-wide formula readability remains a separate layout consideration; no new horizontal-scrolling mode was added.

## Reproducing the development build

From a clean checkout, follow `BUILDING.md` to prepare native dependencies, then run:

```sh
python3 scripts/configure_server_dev.py
cd src/android
./gradlew --no-daemon --max-workers=1 \
  '-Dorg.gradle.jvmargs=-Xmx6g -XX:MaxMetaspaceSize=1g -Dfile.encoding=UTF-8' \
  -Pkotlin.compiler.execution.strategy=in-process \
  :app:testGithubDebugUnitTest \
  --tests 'com.openminis.app.ui.chat.DisplayMath*Test' \
  :app:assembleGithubDebug
```

The configuration script applies build-only Dev 40 overrides: `com.openminis.app.memorytest`, `Minis Dev`, versionCode 40, `1.15-dev`, NDK 28.0.13004108, and disabled debug server/self-updates. It intentionally leaves the APK unsigned. Sign separately with the established private development key; never commit that key, password, SSH configuration or private conversation fixtures. Do not also run the legacy CI configuration script.

See `dev-40-source-sha256.json` for verified changed source inputs. `build.gradle.kts` and the application label deliberately receive workspace-only overrides through the script.
